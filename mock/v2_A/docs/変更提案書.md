## 1. 提案の背景と目的

本提案書は、現在開発中のなにわセレクトショップ ECシステムにおいて、「会員ログイン機能」の実装を今回のリリースから取りやめ、「ゲスト購入のみ」の構成（以下「ゲスト専用構成」）でリリースすることをご提案するものです。

### 1.1 提案に至った経緯

現在のプロジェクト状況は以下の通りです。

| 項目 | 現状 |
|---|---|
| 残り開発期間 | 6日間 |
| 開発体制 | プログラミング初学者 5名 |
| コア機能の実装状況 | 未着手（DB設計・モックアップ完成済み） |
| 会員機能の実装状況 | 未着手 |

残り期間と体制を踏まえた結果、会員ログイン機能の品質を担保したままリリースに間に合わせることが困難と判断いたしました。今回のリリース範囲をゲスト購入専用構成に絞り、品質・納期・スコープのバランスを最適化することを提案します。

---

## 2. 提案内容

### 2.1 今回のリリースで実装する機能

| 機能カテゴリ | 機能名 | 概要 | 対応状況 |
|---|---|---|---|
| 顧客向け | 商品閲覧 | おすすめ・通常商品の一覧・売り切れ表示 | 🔲 未着手 |
| 顧客向け | ゲストカート | localStorageでカート管理（登録不要） | 🔲 未着手 |
| 顧客向け | ゲスト注文 | メールアドレス入力で注文確定 | 🔲 未着手 |
| 顧客向け | 決済モック | カード番号形式チェックのみ（課金なし） | 🔲 未着手 |
| 顧客向け | 注文完了画面 | 注文番号・ステータスの表示 | 🔲 未着手 |
| 管理者向け | 管理者認証 | 管理者専用ログイン画面 | 🔲 未着手 |
| 管理者向け | 注文管理 | 全注文一覧・発送情報入力モーダル・ステータス更新 | 🔲 未着手 |
| 管理者向け | 発送通知メール送信 | 発送済み登録と同時にゲスト宛へ追跡番号入りメールを送信 | 🔲 未着手 |
| 管理者向け | 商品管理 | 商品の追加・編集・削除 | 🔲 未着手 |

> **発送通知メールについて**
>
> お客様のご要望（RFP セクションD「発送が終わったらお客様側からもわかるようにしてほしい」）に基づき、フェーズ1の必須機能として位置づけます。管理者が発送情報入力モーダルで「発送済みにする」を実行した際に、ゲストのメールアドレス宛へ配送業者・追跡番号を記載した通知メールが自動送信されます。実装には外部メールサービス（Resend）との連携が必要です。

> **発送情報入力モーダルについて**
>
> 「発送済みにする」ボタンを押すと、配送業者（選択式）と追跡番号（テキスト入力）を入力するモーダルが表示されます。入力した情報はDBに保存され、同時にゲスト宛へ発送通知メールが送信されます。

## 3. 影響分析

### 3.1 メリット

| 観点 | 内容 |
|---|---|
| 品質の確保 | コア機能（商品閲覧・注文・発送通知・管理）に集中でき、バグリスクを低減できます |
| 納期の遵守 | 残り6日間で確実にリリース可能な範囲に絞ることができます |
| セキュリティ | 会員情報の管理・漏洩リスクがなく、個人情報の保有量を最小化できます |
| 購入体験の向上 | 「登録が面倒」と感じるユーザーの離脱を防ぎ、初回購入のハードルを下げられます |
| お客様への安心感 | 発送通知メールにより、お客様が発送状況を自分で確認できます |

### 3.2 デメリットと対応策

| デメリット | 影響度 | 対応策 |
|---|---|---|
| Resend 外部サービスの学習コストが発生する | 中 | 無料枠で導入でき、Next.jsとの連携ドキュメントが充実しているため比較的短時間で習得可能 |
| リピーター向け購入履歴が確認できない | 中 | ゲストのメールで注文照会は可能。フェーズ2で対応 |
| 注文履歴をお客様が自己確認できない | 中 | 注文番号・発送通知メールで代替。フェーズ2で対応 |
| マーケティング施策に制限がある | 低 | 初期フェーズとして許容範囲。フェーズ2以降に対応 |

## 4. 将来フェーズへの設計上の備え

今回の変更はリリース範囲を絞るものであり、将来の機能追加を困難にするものではありません。以下の設計上の配慮により、フェーズ2以降のスムーズな拡張を保証します。

| 設計上の備え | 詳細 |
|---|---|
| carrier・tracking_numberカラム設計済み | 発送通知メールの本文に埋め込む発送情報をDBで管理 |
| profilesテーブル設計済み | 会員機能追加時にそのまま使えるテーブルを確保。role='customer'として流用可能 |
| cart_itemsテーブル設計済み | DBカート管理への移行用テーブルとRLSポリシーが設定済み |
| orders.user_idカラム確保 | 会員注文とゲスト注文を同一テーブルで管理できる設計。追加コストなし |
| image_urlカラム確保 | 商品画像登録機能追加時にカラム変更なしで対応可能 |
