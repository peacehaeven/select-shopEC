## 1. プロジェクト概要

### 1.1 プロジェクト名

なにわセレクトショップ ECシステム

### 1.2 プロジェクトの目的

大阪の特産品・名産品をオンラインで販売するための ECサイトを構築する。一般顧客がインターネット上で会員登録なしに商品を閲覧・購入でき、ショップ管理者が商品情報と注文状況を管理できるシステムを開発する。

### 1.3 プロジェクトの背景

現在、なにわセレクトショップは実店舗での販売のみで展開しているが、販路拡大と新規顧客獲得のため、オンライン販売チャネルの構築が急務となっている。本プロジェクトでは、プログラミング初学者5名のチームにて、学習と実践を兼ねた ECサイトの開発を行う。

### 1.4 スコープ

#### 1.4.1 対象範囲（フェーズ1）

- **顧客向け機能：** 商品閲覧、ゲストカート操作、ゲスト注文
- **管理者向け機能：** 商品管理（CRUD）、注文管理（ステータス更新・発送情報入力）、管理者認証、発送通知メール送信

#### 1.4.2 対象外（フェーズ2以降で対応）

- 会員登録・ログイン・マイページ（注文履歴）
- 商品画像登録
- レスポンシブデザイン

### 1.5 用語定義

| 用語 | 定義 |
|---|---|
| 顧客（ゲスト） | 会員登録なしに商品を購入する一般ユーザー。メールアドレスのみ入力して購入可能。 |
| 管理者（アドミン） | 商品情報の登録・編集、注文ステータスの管理を行うショップ運営者。 |
| おすすめ商品 | 管理者が「おすすめ」に設定した商品。トップページ上段に優先表示される。 |
| 注文ステータス | 注文の進行状態。「注文受付済み」と「発送済み」の2段階で管理する。 |
| ゲスト注文 | 会員登録なしにメールアドレスのみで行う注文。 |
| 発送情報 | 配送業者名と追跡番号の組み合わせ。管理者が発送時にモーダルへ入力する。 |
| 発送通知メール | 管理者が発送済み登録を行った際に、ゲストのメールアドレスへ自動送信されるメール。配送業者・追跡番号・追跡URLを含む。 |
| RLS | Row Level Security。データベースレベルでユーザーごとのアクセス制御を実現する仕組み。 |

## 2. システム構成

### 2.1 技術スタック

| 層 | 技術 | バージョン | 選定理由 |
|---|---|---|---|
| フロントエンド | Next.js (App Router) | **16.2** | Reactベースで学習資料が豊富。Server Componentsによりサーバーサイドでのデータ取得が可能。 |
| UIライブラリ | React | **19.2** | Next.js 16.2 に同梱。Server ComponentsおよびActionsに対応した最新版。 |
| 言語 | TypeScript | **5.9** | 型安全性を確保。6.0はRC段階のため安定版である5.9を採用。 |
| ランタイム | Node.js | **24.14.0 LTS** | Active LTS版（コードネーム "Krypton"）。本番利用推奨バージョン。 |
| データベース | Supabase (PostgreSQL) | **最新（マネージド）** | 無料枠あり。Dashboard でのGUI操作が可能で初学者に親和性が高い。 |
| DB操作 | @supabase/supabase-js | **2.99.3** | 認証とDB操作を同一ライブラリで統一でき、RLSとの連携がシームレス。 |
| SSR認証連携 | @supabase/ssr | **0.9.0** | Next.js App RouterでのSupabase Auth連携に必要なSSRヘルパー。 |
| 認証 | Supabase Auth | **最新（マネージド）** | 管理者ログインのみに使用。メール+パスワード認証を標準提供。 |
| アクセス制御 | Row Level Security (RLS) | **PostgreSQL標準機能** | データベースレベルの制御で、アプリ側での実装漏れリスクを低減。 |
| カート管理 | localStorage（ブラウザ側） | **Web標準API** | ゲスト専用のためDBカート不要。フェーズ2で会員対応時にDB管理に移行予定。 |
| 決済 | モック実装 | **—** | 本フェーズでは決済フォームのUI、数字16桁のチェックのみ。実際の課金処理は行わない。 |
| メール送信 | Resend | **6.9.4** | 無料枠100通/月。Next.jsとの連携ドキュメントが充実しており初学者でも導入しやすい。 |
| デプロイ | Vercel | **最新（マネージド）** | GitHub連携で自動デプロイ。Next.jsとの親和性が最も高い。 |

## 4. 非機能要件

### 4.1 セキュリティ

| 要件ID | 要件 | 優先度 |
|---|---|---|
| NF-01 | 全テーブルにRow Level Security（RLS）を適用すること | 必須 |
| NF-02 | パスワードはSupabase Authによりbcryptでハッシュ化して保存すること（管理者アカウント） | 必須 |
| NF-03 | 管理者ページへの未認証アクセスはミドルウェアでリダイレクト制御すること | 必須 |
| NF-04 | 管理者権限チェックをミドルウェア（ページアクセス時）とRLS（DB操作時）の二重で実施すること | 必須 |
| NF-05 | 環境変数（APIキー等）はソースコードにハードコードせず、.env.localで管理すること | 必須 |
| NF-06 | .env.localが.gitignoreに含まれ、Gitリポジトリにコミットされないこと | 必須 |
| NF-07 | Resend APIキーを含む外部サービスの認証情報はすべて環境変数で管理すること | 必須 |

### 4.2 性能

| 要件ID | 要件 | 優先度 |
|---|---|---|
| NF-08 | トップページの初回表示が3秒以内に完了すること（通常回線時） | 推奨 |
| NF-09 | 商品一覧はServer Componentで取得し、サーバーサイドレンダリングすること | 必須 |
| NF-10 | SupabaseプロジェクトのリージョンはNortheast Asia (Tokyo)を選択すること | 必須 |

### 4.3 可用性

| 要件ID | 要件 | 優先度 |
|---|---|---|
| NF-11 | VercelおよびSupabaseのマネージドサービスを利用し、インフラ管理を不要とすること | 必須 |
| NF-12 | Supabase無料枠の範囲内で運用可能であること | 必須 |
| NF-13 | Resend無料枠（月100通）の範囲内で運用可能であること | 必須 |

### 4.4 ユーザビリティ

| 要件ID | 要件 | 優先度 |
|---|---|---|
| NF-14 | デスクトップブラウザ（Chrome、Safari、Edgeの最新版）で正常に表示・操作できること | 必須 |
| NF-15 | 主要なエラー（在庫不足・未入力・メール送信失敗等）に対して日本語のエラーメッセージを表示すること | 必須 |

| NF-17 | 価格はすべて税込価格で表示すること | 必須 |
| NF-18 | スマートフォンでの閲覧に対応したレスポンシブデザインとすること | フェーズ2 |

### 4.5 保守性

| 要件ID | 要件 | 優先度 |
|---|---|---|

### 6.2 発送通知メールの仕様

| 項目 | 内容 |
|---|---|
| 送信タイミング | 管理者が発送モーダルで「発送済みにする」を実行した瞬間 |
| 送信先 | orders.guest_email |
| 件名 | 【なにわセレクトショップ】ご注文商品を発送しました |
| 本文に含む情報 | 注文番号、配送業者名、追跡番号、各配送業者の追跡URL |
| 送信失敗時の挙動 | エラーメッセージを管理者画面に表示。DBへのステータス更新は成功済みのため手動で再送可能。 |

### 6.3 ブラウザ対応

対応ブラウザはGoogle Chrome、Safari、Microsoft Edgeの各最新版とする。Internet Explorerは対象外とする。

## 7. 制約条件

### 7.1 技術的制約

Supabase無料プラン（Free Tier）の範囲内で構築する。無料プランの主な制限として、データベース容量500MB、ファイルストレージ1GB、月間APIリクエスト数50万回が存在する。

Resend無料プランの範囲内で構築する。無料プランの制限として、月間100通が存在する。注文件数が月間100件を超える見込みが生じた場合は有料プランへの移行を検討する。

決済処理は本フェーズではモック実装とし、実際のクレジットカード情報の送信・課金は行わない。将来的にStripe等の決済サービスとの連携を想定したUI設計とする。

### 7.2 体制上の制約

開発チームはプログラミング初学者5名で構成される。開発期間は残り6日間。チーム全員が同一の開発環境（Node.js 24.14.0 LTS、VS Code）を使用する。GitのブランチはGitHub Flow（featureブランチ + Pull Request）を採用する。
