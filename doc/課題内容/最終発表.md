# 最終発表（納品レビュー）ガイドライン

各チームの持ち時間は **25分** + 5分(バッファ) です。以下の3セクション構成で発表を行ってください。
「顧客に対する納品報告」であることを意識し、プロのエンジニアチームとして振る舞いましょう。

## 1. デモンストレーション（5分）

**【目的】顧客（講師）の要望が正しく実装されていることを証明する**

* **要望の振り返り:** 顧客から受けた主要な要望（おすすめ機能、在庫連動など）の再確認。
* **実機操作:** 実際にシステムを動かし、以下の流れを実演。
* ユーザーとして：商品の選択 → カート追加 → 擬似決済。
* 管理者として：在庫の更新 → 発送ステータスの変更。


* **正常終了の確認:** 「注文完了」や「在庫切れ表示」など、期待通りの挙動を見せる。

## 2. プロジェクト管理の振り返り（5分）

**【目的】開発工程（doc/）とチーム開発（Git）のプロセスを共有する**

* **QA/課題表の提示:** * どのような質問をし、どう仕様を確定させたか。
* 未完了のタスクや、後回しにした機能（バックログ）の有無。


* **テスト結果の報告:** * 単体・結合テストの実施結果。
* 発見されたバグと、その修正履歴について。


* **Git運用の振り返り:** * ブランチグラフやコミットメッセージを見せながら、チーム内の統合フローを説明。

## 3. 工夫した点と苦労した点（15分）

**【目的】チーム独自のノウハウや、困難をどう乗り越えたかを共有する**

* **技術的な工夫:** * コードの共通化、UI/UXの改善（使いやすさへの配慮）、擬似機能の実装方法など。
* **苦労したポイント:** * Gitのコンフリクト、仕様の解釈違い、時間が足りなかった部分など。
* **チームワークの気づき:** * 役割分担がどう機能したか、Slackでのコミュニケーションで意識したこと。
* **次への課題:** * もし追加で1週間あったら、どこをブラッシュアップしたいか。
