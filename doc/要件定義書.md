## 1. プロジェクト概要

### 1.1 プロジェクト名

なにわセレクトショップ EC システム

### 1.2 プロジェクトの目的

大阪の特産品・名産品をオンラインで販売するための EC サイトを構築する。一般顧客がインターネット上で商品を閲覧・購入でき、ショップ管理者が商品情報と注文状況を管理できるシステムを開発する。

### 1.3 プロジェクトの背景

現在、なにわセレクトショップは実店舗での販売のみで展開しているが、販路拡大と新規顧客獲得のため、オンライン販売チャネルの構築が急務となっている。本プロジェクトでは、プログラミング初学者5名のチームにて、学習と実践を兼ねた EC サイトの開発を行う。

### 1.4 スコープ

#### 1.4.1 対象範囲

- **顧客向け機能：** 商品閲覧、カート操作、注文、注文履歴確認、会員登録・ログイン
- **管理者向け機能：** 商品管理（CRUD）、注文管理（ステータス更新）、管理者認証

#### 1.4.2 対象外（将来対応）

- メール通知（注文確認・発送通知）
- 商品画像登録

### 1.5 用語定義

| 用語 | 定義 |
|---|---|
| 顧客（カスタマー） | 商品を購入する一般ユーザー。会員登録後にカート・注文機能を利用できる。 |
| 管理者（アドミン） | 商品情報の登録・編集、注文ステータスの管理を行うショップ運営者。 |
| おすすめ商品 | 管理者が「おすすめ」に設定した商品。トップページ上段に優先表示される。 |
| 注文ステータス | 注文の進行状態。「注文受付済み」と「発送済み」の2段階で管理する。 |
| RLS | Row Level Security。データベースレベルでユーザーごとのアクセス制御を実現する仕組み。 |

## 2. システム構成

### 2.1 技術スタック

| 層 | 技術 | 選定理由 |
|---|---|---|
| フロントエンド | Next.js (App Router) + TypeScript | React ベースで学習資料が豊富。Server Components によりサーバーサイドでの DB 操作が可能。 |
| データベース | Supabase (PostgreSQL) | 無料枠あり。Dashboard での GUI 操作が可能で初学者に親和性が高い。 |
| DB 操作 | Supabase JS Client (@supabase/ssr) | 認証と DB 操作を同一ライブラリで統一でき、RLS との連携がシームレス。 |
| 認証 | Supabase Auth | メール+パスワード認証を標準提供。JWT ベースでセッション管理が容易。 |
| アクセス制御 | Row Level Security (RLS) | データベースレベルの制御で、アプリ側での実装漏れリスクを低減。 |
| 決済 | モック実装 | 本フェーズでは決済フォームの UI 、数字16桁のチェックのみ。実際の課金処理は行わない。 |
| デプロイ | Vercel | GitHub 連携で自動デプロイ。Next.js との親和性が最も高い。 |

### 2.2 システム構成図

本システムは以下の3層構成で構築する。

1. **クライアント層：** ユーザーのブラウザで動作する Next.js アプリケーション。Vercel 上にホスティング。
2. **認証・API 層：** Supabase が提供する Auth サービスと PostgREST API。JWT トークンによるセッション管理。
3. **データベース層：** Supabase 上の PostgreSQL データベース。RLS ポリシーにより行レベルのアクセス制御を実施。

## 4. 非機能要件

### 4.1 セキュリティ

| 要件ID | 要件 | 優先度 |
|---|---|---|
| NF-01 | 全テーブルに Row Level Security (RLS) を適用し、ユーザーは自身のデータのみアクセス可能とすること | 必須 |
| NF-02 | パスワードは Supabase Auth により bcrypt でハッシュ化して保存すること | 必須 |
| NF-03 | 認証が必要なページへの未認証アクセスは、ミドルウェアでリダイレクト制御すること | 必須 |
| NF-04 | 管理者権限チェックをミドルウェア（ページアクセス時）と RLS（DB 操作時）の二重で実施すること | 必須 |
| NF-05 | 環境変数（API キー等）はソースコードにハードコードせず、.env.local で管理すること | 必須 |
| NF-06 | .env.local が .gitignore に含まれ、Git リポジトリにコミットされないこと | 必須 |

### 4.2 性能

| 要件ID | 要件 | 優先度 |
|---|---|---|
| NF-07 | トップページの初回表示が 3 秒以内に完了すること（通常回線時） | 推奨 |
| NF-08 | 商品一覧は Server Component で取得し、サーバーサイドレンダリングすること | 必須 |
| NF-09 | Supabase プロジェクトのリージョンは Northeast Asia (Tokyo) を選択し、レイテンシを最小化すること | 必須 |

### 4.3 可用性

| 要件ID | 要件 | 優先度 |
|---|---|---|
| NF-10 | Vercel および Supabase のマネージドサービスを利用し、インフラ管理を不要とすること | 必須 |
| NF-11 | Supabase 無料枠の範囲内で運用可能であること | 必須 |

### 4.4 ユーザビリティ

| 要件ID | 要件 | 優先度 |
|---|---|---|
| NF-12 | デスクトップブラウザ（Chrome、Safari、Edge の最新版）で正常に表示・操作できること | 必須 |
| NF-13 | 主要なエラー（認証失敗、在庫不足等）に対して日本語のエラーメッセージを表示すること | 必須 |
| NF-14 | 金額表示は円記号（¥）と 3 桁カンマ区切りで統一すること | 必須 |
| NF-15 | スマートフォンでの閲覧に対応したレスポンシブデザインとすること | 推奨 |

### 4.5 保守性

| 要件ID | 要件 | 優先度 |
|---|---|---|
| NF-16 | TypeScript を使用し、Supabase CLI で生成した型定義により型安全性を確保すること | 必須 |
| NF-17 | DB スキーマ変更時は Supabase マイグレーションファイルで管理すること | 必須 |
| NF-18 | コンポーネントを適切に分割し、再利用可能な構成とすること | 推奨 |

## 7. 制約条件

### 7.1 技術的制約

Supabase 無料プラン（Free Tier）の範囲内で構築する。無料プランの主な制限として、データベース容量 500 MB、ファイルストレージ 1 GB、月間 API リクエスト数 50 万回が存在する。

決済処理は本フェーズではモック実装とし、実際のクレジットカード情報の送信・課金は行わない。将来的に Stripe 等の決済サービスとの連携を想定した UI 設計とする。

### 7.2 体制上の制約

開発チームはプログラミング初学者 5 名で構成される。開発期間は 4 週間を想定する。

チーム全員が同一の開発環境（Node.js v20 以上、VS Code）を使用する。Git のブランチ運用は GitHub Flow（feature ブランチ + Pull Request）を採用する。

## 8. 受入条件

### 8.1 顧客フローの受入条件

| テストID | テスト項目 | 期待結果 |
|---|---|---|
| AT-01 | 新規会員登録 | 名前・メール・パスワードを入力して会員登録が完了し、トップページに遷移する |
| AT-02 | ログイン | 登録済みのメール・パスワードでログインが成功し、トップページに遷移する |
| AT-03 | 商品一覧表示 | おすすめ商品が上段、通常商品が下段に表示され、売切商品のボタンが無効になっている |
| AT-04 | カート追加 | 「カートに入れる」クリックでカートに商品が追加され、ナビバーのカート数が増える |
| AT-05 | カート数量変更 | ＋/−ボタンで数量が変更され、小計・合計が即座に再計算される |
| AT-06 | カート商品削除 | 削除ボタンでカートから商品が除去される |
| AT-07 | 注文確定 | 配送先入力後に注文を確定すると注文完了画面に遷移し、注文番号が表示される |
| AT-08 | 在庫不足エラー | 在庫を超える数量で注文すると、エラーメッセージが表示され注文が中止される |

| AT-10 | ログアウト | ログアウト後、保護ページへのアクセスがログイン画面にリダイレクトされる |
