## 2. 実装ルール（絶対遵守）

### 2.1. `proxy.ts` の利用（Middlewareの禁止）
* `middleware.ts` は使用・生成しないこと。
* 代わりにプロジェクトルート（または `src/` 配下）に `proxy.ts` を配置し、`proxy` 関数としてエクスポートすること。
* ランタイムはNode.jsとし、Edgeランタイムの制約は考慮しなくてよい。

### 2.2. セッションの維持（proxy.ts内）
* `proxy.ts` 内で `@supabase/ssr` の `createServerClient` を使用すること。
* Cookieの `getAll` および `setAll` を用いたセッショントークンのリフレッシュ処理を**必ず実装**すること（省略不可）。

### 2.3. 責務の分離（認可ロジック）
* **proxy.ts:** Cookieの更新と、未ログイン時の `/login` への単純なリダイレクトのみを行う。
* **Server Components / Server Actions:** 権限チェック（管理者確認）、DBクエリを伴う認可ロジックなど、複雑なデータアクセス層の処理を行う。
