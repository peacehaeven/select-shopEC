RLS（アクセス制御）

🔒
RLS（Row Level Security）とは？「誰がどの行を見られるか」をDBが自動チェックする仕組み。アプリ側の実装漏れがあってもDBレベルで守れます。
Supabaseのロールとは
anon（未ログイン）
auth.uid()NULL
auth.role()'anon'
ゲスト購入するお客様
authenticated（ログイン済み）
auth.uid()ユーザーID
auth.role()'authenticated'
管理者がログインするとこれ
ポリシー一覧
テーブル操作誰が条件
productsSELECT🌐 全員（ゲスト含む）無条件
productsINSERT UPDATE DELETE🔑 管理者のみrole = 'admin'
ordersINSERT👤 ゲストのみ未ログイン ＋ guest_email あり
ordersSELECT UPDATE🔑 管理者のみrole = 'admin'
order_itemsINSERT👤 ゲストのみ対応する orders がゲスト注文
order_itemsSELECT🔑 管理者のみrole = 'admin'
profilesSELECT🙋 本人 or 管理者id 一致、または admin
cart_items全操作🙋 本人のみuser_id 一致（将来の会員用）
🚨 RLS デバッグ TIPS

permission denied が出たら RLS が原因の可能性があります。

📍 確認場所
Dashboard → Table Editor
→ 該当テーブル
→「RLS policies」
-- SQL Editorで実行（確認後はRESET ROLEすること）
SET ROLE postgres;   -- RLSを回避
SELECT * FROM orders;
RESET ROLE;          -- ← 忘れずに

注文処理の流れ（place_guest_order）

place_guest_order() を1回呼ぶだけで在庫チェック〜注文作成〜在庫減算をまとめて処理します。

処理のステップ
0
ガードチェック
ログイン済みユーザーなら即エラー
1
カート空チェック
空なら即エラーを返す
2
在庫チェック
1個でも不足 → 全処理中止
3
小計計算
単価 × 数量 の合計
4
orders に INSERT
→ トリガーが注文番号を自動採番
5
order_items に INSERT
商品名・価格をスナップショット保存
6
stock を減算
在庫を注文数分だけ減らす
↩
注文IDを返す
フロントはIDで注文番号を取得
トランザクションとは？

ステップ4〜6は「一体不可分のひとかたまり」として実行されます。途中でエラーが起きると全処理が自動でなかったことになります（ロールバック）。

❌ なしだと…
ステップ5でエラー → 注文作成だけ残る 😱
✅ あると…
ステップ5でエラー → ステップ4も自動取り消し ✅
フロントからの呼び出し方

ゲスト注文処理（place_guest_order）

    p_guest_email: '[email protected]',

キャンセル処理の流れ

全体の流れ
管理者の操作
「キャンセルする」
ボタンをクリック
→
確認モーダルが開く
「この操作は取り消せません」
「在庫が自動で戻ります」
→
① cancel_order() DB関数を呼び出すstatus = 'cancelled' に UPDATE
在庫を注文数分だけ加算（戻す）
② 画面を更新カードが「キャンセル済み」表示に切り替わる
ステータス変更ボタンが非表示になる
⚠️
キャンセルできるのは pending（発送前）の注文のみです。shipped の注文はキャンセル不可です。
cancel_order() 関数の仕組み

DB関数をトランザクション内で実行することで、ステータス更新と在庫戻しを一体として処理します。

-- SQL_3 / SQL_4 で登録済みの DB 関数
CREATE OR REPLACE FUNCTION cancel_order(p_order_id UUID)
RETURNS VOID AS $$
BEGIN
  -- pending 以外はエラー
  IF status <> 'pending' THEN
    RAISE EXCEPTION '発送前の注文のみキャンセルできます';
  END IF;

  -- ① ステータスを cancelled に更新
  UPDATE orders SET status = 'cancelled'
    WHERE id = p_order_id;

  -- ② 在庫を注文数分だけ戻す
  UPDATE products SET stock = stock + oi.quantity
    FROM order_items oi
    WHERE products.id = oi.product_id
      AND oi.order_id = p_order_id;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;
フロントからの呼び出し方（Server Action）
// app/admin/orders/actions.ts
await supabase.rpc('cancel_order', {
  p_order_id: orderId,
});
